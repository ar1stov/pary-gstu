# Выпуск версии

Аргументы: `$ARGUMENTS` — первое слово это новая версия (`1.3`), остальное это текст «что нового» для заметки релиза.
Если версии нет в аргументах или она не новее текущей, остановись и спроси. Сравнение идёт по частям через точку, как числа (`Versions.isNewer`): `1.22` новее и `1.3`, и `1.4` (22 > 4 > 3). Новой считается версия, у которой первая отличающаяся часть больше: после `1.22` подходят `1.23`, `1.30`, `2.0`, а `1.3` и `1.4` нет: приложения не покажут плашку обновления. Перед выпуском проверь, что `isNewer(<новая>, <текущая>)` истинно (например, коротким тестом).

Релиз публикует файлы для всех одногруппников и запускает рассылку в Telegram-чат группы, поэтому перед шагами 7 и 8 покажи пользователю итог (версия, список файлов, заметка релиза) и дождись «да». Всё до этого безопасно.

## Что нужно знать

- Репозиторий: `ar1stov/pary-gstu`, ветка `main`.
- Обновление внутри приложения ищет в релизе файлы с точными именами `Pary-GGTU-<версия>.apk` и `Pary-GGTU-<версия>.apk.sha256`. С другими именами приложения не смогут обновиться.
- Релиз нужно подписывать ключом из `keystore.properties` (сам `.jks` лежит вне проекта). Без него APK соберётся неподписанным или debug-ключом, и поверх установленной версии не встанет. Если `keystore.properties` нет, остановись и скажи об этом.
- R8 выключен, lint release пропускается флагами ниже. Не включай их обратно.
- Для Gradle нужна Java из Android Studio: `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`. Для `apksigner` и `aapt2` переменную `JAVA_HOME` нужно снять (`unset JAVA_HOME`).

## Шаги

1. **Проверить состояние.** `git status` и `git log --oneline -3`. Если есть чужие несохранённые правки, покажи их и спроси, включать ли их в релиз. Прочитай текущие `versionCode` и `versionName` в `app/build.gradle.kts`.

2. **Поднять версию** в `app/build.gradle.kts`: `versionCode` на 1, `versionName` на новую версию.

3. **Прогнать тесты:**
   ```bash
   JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew testDebugUnitTest
   ```
   Если тесты падают, останови выпуск и покажи, какие именно.

4. **Собрать release:**
   ```bash
   JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew assembleRelease -x lintVitalAnalyzeRelease -x lintVitalReportRelease -x lintVitalRelease
   ```
   Результат: `app/build/outputs/apk/release/app-release.apk`.

5. **Подготовить файлы** в `C:\Users\Mechrevo\Downloads\` (так они лежали у прошлых версий):
   - скопировать APK в `Pary-GGTU-<версия>.apk`;
   - посчитать SHA-256 и записать `Pary-GGTU-<версия>.apk.sha256` в формате `<хэш>  Pary-GGTU-<версия>.apk` (два пробела, как у `sha256sum`).

6. **Проверить APK** (с `unset JAVA_HOME`): через `aapt2 dump badging` убедиться, что `package` это `com.example.pary`, `versionCode` и `versionName` новые; через `apksigner verify --print-certs` убедиться, что отпечаток SHA-256 сертификата равен `ebbd91e6b09b19ef3feecf0d5faa1f291470d73f66788d9291350fb5bc055aac`. Не совпал: подпись другая, обновления поверх установленной версии не встанут, выпуск остановить.

7. **Коммит и отправка** (после «да» пользователя). Сообщение на русском в стиле прошлых: `Версия <версия>: <коротко что нового>`. Коммитить только то, что относится к релизу. `git push origin main`.

8. **Создать релиз:**
   ```bash
   gh release create v<версия> --repo ar1stov/pary-gstu --title "Пары ГГТУ <версия>" --notes "<что нового>" Pary-GGTU-<версия>.apk Pary-GGTU-<версия>.apk.sha256
   ```
   В заметке: что нового простыми словами, как обновиться (у кого 1.2 и новее плашка в приложении; у 1.0 и 1.1 нет проверки, ставить вручную по ссылке) и контакт для багов `@qwertyarstv`.

9. **Проверить результат:**
   - `gh run list --repo ar1stov/pary-gstu --workflow telegram-release.yml --limit 1` до статуса `completed success` (рассылка в чат идёт сама при публикации релиза). Не опрашивай в цикле: проверь пару раз с паузой, при ошибке покажи лог `gh run view --log-failed`.
   - `curl -sI https://github.com/ar1stov/pary-gstu/releases/latest` и убедиться, что `location` ведёт на `v<версия>`.
   - Скачать APK и `.sha256` по публичной ссылке (ответ 200) и сверить сумму.

10. **Обновить `CLAUDE.md`**, если изменились шаги выпуска или появилось что-то новое для будущих версий.

## Итог для пользователя

Коротко: ссылка на релиз, что проверено (подпись, версия, сумма, рассылка), что не проверено (например, установка на чужих телефонах), и кому придётся ставить вручную.
