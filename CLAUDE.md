# Pary

Android-приложение с расписанием пар для студентов ГГТУ.

## Цель проекта

- Показывать расписание пар для выбранной студентом группы.
- Выбор группы при первом запуске, возможность сменить её позже.
- Виджет расписания на главном экране телефона (сделан).

## Текущее состояние

Готово: выбор группы (поиск по API), сохранение группы на устройстве, экран расписания по дням и неделям,
кэш расписания на телефоне, два виджета на главный экран (Jetpack Glance: 4×3 и 4×2), напоминание о первой паре, отметка изменений в расписании, release-сборка.

## Источник данных

Открытый JSON API сайта `https://sc.gstu.by/api` (не документирован, может измениться):
- `GET /schedules/autocomplete?q=<текст>` — поиск групп, максимум 10 за запрос (`hasMore` — есть ещё).
- `GET /schedules/group/<slug>` — расписание группы (`slug` вроде `ip-21`).
- `weekType`: `EVEN` = «над чертой», `ODD` = «под чертой», `ALL` = каждую неделю.
- Подгруппы: у пары в `groups[]` запись самой группы (по `slug`) содержит `subgroups`; нет списка — пара для всей группы. Выбранная подгруппа хранится в DataStore (0 — все).
- Чередование недель сайт считает от 01.09.2025: первая неделя — «над чертой» (`Dates.isAboveWeek`).

## Стек

- Kotlin, Jetpack Compose + Material 3 (интерфейс без XML-разметки)
- Gradle (Kotlin DSL), версии библиотек в `gradle/libs.versions.toml`
- Пакет и applicationId: `com.example.pary`
- minSdk 24, targetSdk 37

## Структура

- `app/src/main/java/com/example/pary/` — код приложения
  - `MainActivity.kt` — точка входа: показывает выбор группы или расписание
  - `data/` — модели (`Lesson.kt`), сеть (`ScheduleApi`), разбор JSON (`ScheduleParser`),
    кэш и загрузка (`ScheduleRepository`), выбранная группа (`GroupRepository`), даты (`Dates`)
  - `notify/` — напоминания (`Reminders`, будильник), уведомления, приёмники `ReminderReceiver` и `BootReceiver`
  - `widget/` — виджеты `ScheduleWidget` (Glance) и его ресивер; читает тот же кэш, что и приложение
  - `ui/` — экраны `GroupSelectScreen` и `ScheduleScreen`
  - `ui/theme/` — цвета, шрифты, тема (`Color.kt`, `Type.kt`, `Theme.kt`)
- `app/src/main/res/` — ресурсы: строки (`values/strings.xml`), цвета, иконки, XML-настройки
- `app/src/main/AndroidManifest.xml` — описание приложения и его экранов
- `app/src/test/` — юнит-тесты; `app/src/androidTest/` — тесты на устройстве
- `app/build.gradle.kts` — настройки модуля и зависимости
- `build.gradle.kts`, `settings.gradle.kts` — настройки всего проекта

## Планы по реализации

- Виджет обновляется системой раз в ~30 минут и при смене группы или обновлении расписания в приложении.

## Уведомления и изменения

- Напоминания ставятся будильником (`Reminders`): режим «первая пара» (`ReminderMode.FIRST_ONLY`) или «каждая пара» (`EVERY_LESSON`; напоминание о следующей паре не раньше конца предыдущей, пары с одним временем начала считаются одной); без разрешения «Будильники и напоминания» оно срабатывает в окне до ~10 минут. Настройки — колокольчик в шапке.
- При каждом обновлении `ScheduleRepository.refresh` сравнивает расписание с прежним (`ScheduleDiff`): изменения хранятся до нажатия «Понятно» и показываются плашкой; фоновое обновление из виджета присылает уведомление.
- Виджеты обновляются по границам пар через `WidgetScheduler` (будильник), а не только раз в ~30 минут.

## Удобство для студента (версия 2.0)

- Фоновая проверка расписания раз в час (`notify/ScheduleSync`, WorkManager, ночью с 23 до 6 не работает): присылает уведомление об изменениях и обновляет виджеты.
- Сводка дня (`notify/Digests`): утренняя о сегодняшнем дне и вечерняя о завтрашнем, в дни без пар не приходит; будильники ставятся как у напоминаний (`Reminders`). В сводке видны заметки.
- Сводка показывает пары выбранной подгруппы; при «Все подгруппы» у пар для части группы стоит подпись «подгр. N». Кнопка примера сводки показывает по одному примеру на каждый включённый переключатель (утренний — сегодня, вечерний — завтра).
- Строки виджета всегда получают фон (у неподсвеченных он прозрачный): иначе RemoteViews оставляет подсветку «текущей пары» на строке после перерисовки.
- Заметки к парам (`data/NotesRepository`): ключ «группа|день|время|предмет», хранятся в DataStore, старше 30 дней удаляются. Нажатие на карточку пары открывает заметку.
- «Переход между корпусами» (`DayItem.Transfer`, `buildingOf`): номер корпуса берётся из аудитории «2-335» до дефиса; показывается, если окна нет, а корпус другой; перемена до 10 минут подсвечивается.
- Обзор недели (значок календаря в шапке), недавние группы (`GroupRepository.recentGroups`, подгруппа запоминается для каждой группы), меню ⋮ (поделиться днём, экспорт .ics через `FileProvider` на 28 дней), ярлыки на иконке (`res/xml/shortcuts.xml`, действие `com.example.pary.OPEN_DAY`).
- Экран настроек `ui/SettingsScreen` (вместо диалога): тема, напоминания, сводки, изменения, проверка разрешений (уведомления, точные будильники, оптимизация батареи), «О приложении» с проверкой обновлений и кнопкой «Сообщить об ошибке».
- «Что нового» показывается один раз после обновления (`lastSeenVersion`); текст `whats_new_body` в `strings.xml` нужно обновлять к каждому релизу.
- Виджеты перечитывают данные при каждом обновлении (`WidgetVersion`): пока сессия Glance жива, `updateAll` не вызывает `provideGlance` заново, и без этого виджет показывал бы старую подгруппу.

## Обновления внутри приложения

- `update/`: при запуске (не чаще раза в полчаса) `UpdateChecker` спрашивает `github.com/<repo>/releases/latest` без перехода по ссылке и по адресу переадресации узнаёт тег последнего релиза (так не тратится лимит API GitHub).
- Скачивание: `Pary-GGTU-<версия>.apk` и `Pary-GGTU-<версия>.apk.sha256` из релиза; проверяются сумма SHA-256, имя пакета, что версия новее и что подпись совпадает с установленной. Установка идёт через `PackageInstaller`, подтверждение остаётся за пользователем.
- **Каждый релиз должен содержать оба файла с точными именами** (`Pary-GGTU-1.3.apk` и `Pary-GGTU-1.3.apk.sha256`), иначе приложения не смогут обновиться.
- Приложения со сборкой, подписанной другим ключом (например, debug), обновить на месте нельзя: приложение предупредит об этом.

## Release-сборка

- `./gradlew assembleRelease -x lintVitalAnalyzeRelease -x lintVitalReportRelease -x lintVitalRelease` -> `app/build/outputs/apk/release/app-release.apk`.
- Версии сравниваются по частям через точку как числа (`Versions.isNewer`): `1.22` новее и `1.3`, и `1.4`, и `1.9`. После `1.22` выпускать можно только `1.23` и выше или `2.0`; `1.3` и `1.4` приложения версий 1.2–1.22 не примут за обновление (плашка не появится). Проверять так: `isNewer(новая, установленная)` должно быть true.
- Перед выпуском поднять `versionCode` и `versionName` в `app/build.gradle.kts`, назвать файл `Pary-GGTU-<версия>.apk`, рядом положить `.sha256` (формат `<хэш>  <имя файла>`).
- Подпись берётся из `keystore.properties` (в репозиторий не попадает); сам ключ (`.jks`) хранится вне проекта, путь к нему указан в `keystore.properties`. Ключ и пароль нужно сохранить: без них приложение нельзя будет обновить поверх установленного.
- R8 (`optimization.enable`) выключен: после оптимизации виджеты Glance не рисовались.
- Lint release пропускается: в этом окружении не скачивается его служебная библиотека.
- `applicationId` пока `com.example.pary`: для Google Play его нужно сменить (префикс `com.example` не принимается).

## Тема

- Две палитры в `ui/theme/Color.kt` (`ParyColors.Dark` и `ParyColors.Light`); в коде экранов цвета берутся из `MaterialTheme.pary`, а не напрямую. Выбор «Авто / Светлая / Тёмная» хранится в настройках (`ThemeMode`).
- Виджеты показывают светлую палитру днём и тёмную ночью по системной теме телефона (`ColorProvider(day, night)`); у них нет собственного переключателя.
- Контраст палитр проверяет тест `PaletteContrastTest`: новые цвета нужно прогнать через него.

## Заметки по экрану расписания

- Дни листаются свайпом: `HorizontalPager` из 6 страниц на неделю (Пн–Сб) на ±52 недели; плитки дней и переключатель недель управляют той же `pagerState`. У пейджера обязательно `verticalAlignment = Alignment.Top`, иначе короткий день «плавает» посередине экрана.
- «Окно» (`dayItems`) показывается при паузе от 45 минут между концом предыдущих пар и началом следующей; обычные перемены (10–30 минут) и пары подгрупп в одно время окон не создают.

## Заметки по виджету

- Не использовать `Spacer(GlanceModifier.padding(...))`: на проверенном телефоне (OnePlus, ColorOS) всё, что шло после него, не отрисовывалось. Отступы задавать через `padding` у самого элемента.

## Соглашения

- UI пишем на Compose, новые экраны — отдельными `@Composable`-функциями.

- Тексты для пользователя — в `strings.xml`, на русском.
